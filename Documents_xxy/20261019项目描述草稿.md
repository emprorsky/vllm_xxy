**vLLM KV-Aware Scheduling：面向 Coding Agent 的跨层推理调度与 KV Cache 优化｜独立项目**

面向多轮 Coding Agent 的共享前缀与有限显存场景，基于vLLM V1扩展实例内准入、
多实例请求放置和CPU缓存写入准入，使用4×RTX3080Ti构建公开轨迹回放、机制负载与跨层消融。

技术栈：Python、PyTorch、vLLM V1、Paged KV Cache、APC、LMCache、NIXL、CUDA Graph。

1. **实例内调度**：实现Top-W缓存亲和准入、恢复重算成本感知抢占及aging保护，
   通过KV generation失效与懒解析维护本地特征一致性。在BF16自然容量、8K上下文、
   32会话对照中，三轮吞吐中位数提升33.80%；独立32任务验证提升19.09%，并评估TTFT尾延迟代价。
2. **缓存与负载联合路由**：借鉴Preble，维护在途请求账本，按真实输出token更新剩余工作，
   用FIFO批处理槽位与KV预算近似排队，保留缓存/负载阈值强基线和同状态串行影子模型。
   双副本4K Coding回放中，三轮吞吐中位数提升6.55%、TTFT P95降低约11.82%；
   同一选中实例上，三轮TTFT预测MAE中位数由6.82秒降至1.66秒。
3. **CPU KV保存准入与正确性**：借鉴EfficientAgent，以会话工作集、真实驻留量和容量淘汰
   共同触发写入过滤，冻结请求决定并在遥测过期时恢复正常保存；修复打包KV形状初始化适配，
   通过字节复制和11项模型恢复检查。在decode Graph对照下，三轮吞吐提升7.46%、
   Stored tokens减少91.41%，相对关闭offload吞吐提升4.02%；独立任务集eager验证提升3.64%。
4. **多卡架构与可复核评估**：实现严格P→D元数据交接、会话信息透传和必需传输/可选CPU保存分离，
   已验证1P1D真实NIXL传输并完成2P2D及同资源副本首轮；更强四配对验收与三轮架构比较仍在执行。
   开展chunk budget、权重量化与KV精度敏感性，保留未通过数值门禁和性能退化的配置。

使用边界：

- 上述6.55%路由、本地调度和独立任务CPU结果限定eager/native RMSNorm/Triton；
  CPU主结果7.46%限定同配置FULL_DECODE_ONLY Graph，不能混为同一组A/B。
- 33.80%本地吞吐提升伴随TTFT P95约4.85%退化；独立任务验证TTFT P95约17.14%退化。
  不将它写成所有延迟指标同时改善，也不在无抢占配置中归因于抢占优化。
- 数据是记录历史输入与依赖顺序的文本回放，固定输出工作预算、模拟工具间隔，
  不执行工具、不测SWE-bench修复率，不称为真实生产到达分布。
- 权重量化、Graph、NIXL搬运与LMCache基础存取属于已有能力；自己的贡献是策略、
  状态/生命周期适配、故障定位修复及可复核消融，不声称原创论文算法或完整复现论文。
- 默认预编译算子在本机未通过验收，工作路径经过显式选择；不把该环境的绝对性能推广到健康默认CUDA路径。

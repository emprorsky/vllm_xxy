# 项目描述

**vLLM KV-Aware Scheduling：面向 Coding Agent 的跨层推理调度与 KV Cache 优化｜独立项目**

面向多轮 Agent 共享前缀与有限显存场景，基于 vLLM V1 扩展实例内准入、跨实例放置与
分层 KV 保存策略，在 4×RTX3080Ti 上构建公开 Coding 轨迹回放、独立任务验证与跨层消融。

技术栈：Python、PyTorch、vLLM V1、Paged KV Cache、APC、LMCache、NIXL、CUDA Graph。

1. **KV 感知调度**：实现 Top-W 缓存亲和准入、重算成本感知抢占与 aging，
   通过 KV generation 失效和懒解析维护特征一致性；BF16 自然容量、8K 上下文、
   32 会话的三轮对照吞吐中位数提升 **33.80%**，独立任务验证提升 **19.09%**，并量化尾延迟代价。
2. **缓存与负载联合路由**：借鉴 Preble，按真实输出进度更新剩余工作，引入受 batch 槽位与
   KV 预算约束的 FIFO 排队近似；双副本 4K Coding 回放吞吐提升 **6.55%**、TTFT P95 降低 **11.82%**，
   同决策、同实例的串行影子 TTFT 预测 MAE 中位数由 **6.82s 降至 1.66s**；独立任务吞吐提升 **7.96%**。
3. **分层缓存写入准入**：借鉴 EfficientAgent，结合会话工作集、真实驻留与容量淘汰抑制无效保存，
   完成决定冻结、异常清理与遥测过期处理；修复打包 KV 初始化及部分 GPU 前缀加载边界，
   通过字节与模型恢复检查。相同 decode Graph 配置下，CPU 准入吞吐提升 **7.46%**、
   Stored tokens 减少 **91.41%**；扩展到文件层的三轮吞吐提升 **2.37%**。
4. **多卡验收与机制归因**：完成 1P1D、2P2D、三卡角色比例及四卡同资源架构三轮对照，
   实现严格元数据交接、必需 NIXL 传输与可选 CPU 保存解耦；用 19 项数值/前缀事实检查覆盖四种
   P→D 配对。评估 chunk budget、AWQ 与 INT8 KV 的适用边界，保留性能退化与数值失败证据。

## 数字使用边界

- 所有主打提升均来自各自配置内三轮中位数，不能相加；三轮是小样本，不称统计显著。
- 第1条自然容量 eager：TTFT P95 原任务 **+4.85%**，独立任务 **+17.14%**；均不能写成延迟全面改善。
  无抢占对照主要支持准入/复用贡献，不用它证明抢占算法增量。
- 第2条限定 eager/native RMSNorm/Triton。Graph 下内存模型相对串行剩余工作模型吞吐仅 **+0.46%**，
  不把预测更准包装为普适吞吐收益。目录和内存约束均为估计，非物理驻留 oracle。
- 第3条 CPU 相对关闭 offload，在相同 Graph 下为 **+4.02%**，eager 下为 **−0.33%**。
  Stored tokens 是 LMCache 日志口径，不直接等同于物理写带宽。文件层 buffered read 可能命中 OS 页缓存。
- 数据为公开轨迹的历史文本回放，固定输出预算、模拟工具间隔，不执行工具、不评价任务修复成功率。
- APC/Graph/量化/搬运/LMCache 基础存取为已有能力；贡献在策略、状态适配、故障修复和消融，
  不声称原创论文算法或完整复现 Preble/EfficientAgent。默认预编译算子本机异常，工作路径经过显式验收。
- 2P2D CPU 联合补验曾在诊断HTTP交接中失败一次，根因尚未定位；成功性能与失败尝试同时报告，
  不将该扩展称为已达到生产稳定性。独立NIXL四卡架构三轮均成功。

四卡最终三轮与 CPU 迁移成功配对已完成，具体资源、失败尝试和边界以《20261019实验报告.md》为准。
